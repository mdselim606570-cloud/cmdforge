# Contributing

## Requirements

- Rust via `rust-toolchain.toml` (currently 1.92, with `rustfmt` and `clippy`)
- Node.js 20 and npm (for Prettier)
- `pwsh` only if you regenerate PowerShell specs

## Setup

```bash
npm ci
cargo build
```

## Validate before opening a PR

```bash
./script/presubmit
```

That script is what CI runs: Prettier check over the JSON specs, `cargo fmt --check`, `cargo clippy ... -D warnings`, and `cargo test`. Fix formatting with `npm run format` and `cargo fmt` rather than by hand.

## Where things live

| Path | Contents |
|------|----------|
| `cmdforge/json/*.json` | Hand-written command specs |
| `cmdforge/json/autogenerated/powershell/` | Generated PowerShell specs — never edit by hand |
| `cmdforge/json/overrides/powershell/` | Hand-written augmentation for generated specs |
| `cmdforge/src/generators/` | Rust generators that produce dynamic completions |
| `completion-metadata/` | Core types and the Fig-compatible schema |

## Adding or changing completions

- Adding a spec or a generator: follow the repository skills in `.agents/skills/`, starting with `add-command-spec`.
- Generated PowerShell output is produced with `cargo run --bin autogenerate_powershell`. It needs `pwsh`; the installed PowerShell version affects the output, so mention the version in the PR if the output changed.
- Overrides are matched by option name or argument index. Only `template` and `generatorName` are supported today.

## Commits and PRs

- Follow [`GIT_WORKFLOW.md`](./GIT_WORKFLOW.md): Conventional Commits, atomic commits, one responsibility each.
- Keep regenerated spec output in its own commit, after the generator or override change that caused it.
- Do not commit `target/`, `node_modules/`, or `Cargo.lock`. The lockfile is intentionally untracked because both crates are libraries.
